# STORY-UL30: Consciousness On/Off Test Bed

As the operator I want every task under this maintenance directive to record whether it ran
with the consciousness loop on or off so that this repo doubles as a natural, ongoing
experiment comparing autonomous-loop and interactive-mode outcomes over time.

## Recommendation (per MSG-EGLPK006 item 4: "do the recommended")

This is a cross-cutting recording convention, not a standalone body of work — it is
satisfied by every task card under DIRECT-UL26 carrying the field below, not by a separate
deliverable of its own.

- [ ] Every task card filed under DIRECT-UL26 (this directive) includes an `## Execution`
      field: `Consciousness loop: on | off` — recorded honestly at claim time from the
      session's actual mode (the framing header states this every turn: "conscious
      autonomy" vs "interactive"), not inferred after the fact
- [ ] A running note is kept (this card, or `CONSCIOUSNESS/artifacts/consciousness-test-bed-log.md`
      once there is enough data to be worth a dedicated file) tallying on/off task counts
      and, where observable, any quality or speed difference between the two modes
- [ ] No task under this directive is claimed without first recording which mode it ran
      under
